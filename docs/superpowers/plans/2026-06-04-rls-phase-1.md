# RLS Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Postgres Row-Level Security as a DB-level tenant-isolation backstop, proven end-to-end on a pilot slice (`school_courses` + `student_course_plans`).

**Architecture:** An `AsyncLocalStorage` request context carries `{ schoolId, userId, isSuperAdmin }`. A Prisma `$extends` query extension wraps each model operation in an array-form `$transaction([ set_config('app.current_school_id', …, true), query ])` so the GUC and the query share one connection (correct under a transaction-mode pooler) while external I/O stays outside DB transactions. RLS policies on the pilot tables enforce `school_id = current_setting('app.current_school_id')::uuid OR bypass`.

**Tech Stack:** Express 5, Prisma 6.8 (`@prisma/client`), Postgres, vitest 4, Node 22 `async_hooks`.

**Spec:** `docs/superpowers/specs/2026-06-04-rls-phase-1-design.md`

```ts
// api/src/lib/requestContext.ts
import { AsyncLocalStorage } from "node:async_hooks";

export type TenantContext =
  | { schoolId?: string; userId?: string; isSuperAdmin: boolean }
  | { system: true };

const storage = new AsyncLocalStorage<TenantContext>();

export function getTenantContext(): TenantContext | undefined {
  return storage.getStore();
}

export function runWithTenantContext<T>(
  ctx: { schoolId?: string; userId?: string; isSuperAdmin: boolean },
  fn: () => T,
): T {
  return storage.run(ctx, fn);
}

export function runAsSystem<T>(fn: () => T): T {
  return storage.run({ system: true }, fn);
}
```

```ts
import { Request, Response, NextFunction } from "express";
import { normalizeRole, ROLES } from "../lib/auth.js";
import { runWithTenantContext } from "../lib/requestContext.js";

// Runs AFTER `authenticate`. Carries the caller's tenant into AsyncLocalStorage
// for the rest of the request so the Prisma RLS extension can set the GUC.
export function tenantContext(req: Request, res: Response, next: NextFunction) {
  const isSuperAdmin = normalizeRole(req.userRole) === ROLES.SuperAdmin;
  runWithTenantContext(
    { schoolId: req.schoolId || undefined, userId: req.userId, isSuperAdmin },
    () => next(),
  );
}
```

- [ ] **Step 3: Write the pure helpers in `prismaRls.ts` (no `prisma` import — avoids a circular import)**

`prismaRls.ts` must NOT import from `prisma.ts`. It holds only pure logic + helpers that take a client/tx as an argument. This keeps imports one-directional (`prisma.ts` → `prismaRls.ts`), so the `$extends` call at module-init time can't hit a TDZ on a half-initialized `basePrisma`.

```ts
// api/src/lib/prismaRls.ts
import { Prisma } from "@prisma/client";
import { getTenantContext, type TenantContext } from "./requestContext.js";

export type GucPlan =
  | { mode: "bypass" }
  | { mode: "deny" }
  | { mode: "school"; schoolId: string };

// Pure decision function — easy to unit test.
export function resolveGucPlan(ctx: TenantContext | undefined): GucPlan {
  if (!ctx) return { mode: "bypass" };          // scripts/seeds/cron: no request context
  if ("system" in ctx) return { mode: "bypass" };
  if (ctx.isSuperAdmin) return { mode: "bypass" };
  if (ctx.schoolId) return { mode: "school", schoolId: ctx.schoolId };
  return { mode: "deny" };                       // authenticated but no tenant -> see nothing
}

// Minimal structural type: anything with Prisma's tagged-template $executeRaw.
type RawExec = { $executeRaw: (q: TemplateStringsArray, ...v: unknown[]) => Prisma.PrismaPromise<number> };

// Returns the (un-awaited) GUC PrismaPromise for `client`. `true` => SET LOCAL
// (tx-scoped). Usable both in array-form $transaction and (awaited) inside an
// interactive tx. Caller guarantees this runs in the SAME tx as the real query.
export function gucOp(client: RawExec, plan: GucPlan): Prisma.PrismaPromise<number> {
  if (plan.mode === "school") {
    return client.$executeRaw`SELECT set_config('app.current_school_id', ${plan.schoolId}, true)`;
  }
  if (plan.mode === "bypass") {
    return client.$executeRaw`SELECT set_config('app.bypass_rls', 'on', true)`;
  }
  // deny: set bypass explicitly off; policies then match neither school nor bypass.
  return client.$executeRaw`SELECT set_config('app.bypass_rls', 'off', true)`;
}

// For use inside existing interactive `$transaction(async (tx) => ...)` blocks:
// sets the GUC on the tx connection as the first statement.
export async function setTenantGuc(tx: Prisma.TransactionClient): Promise<void> {
  await gucOp(tx as unknown as RawExec, resolveGucPlan(getTenantContext()));
}
```

- [ ] **Step 4: Build the extended client in `api/src/lib/prisma.ts` (base + extension live together — no cycle)**

```ts
// api/src/lib/prisma.ts
import { PrismaClient } from "@prisma/client";
import { getTenantContext } from "./requestContext.js";
import { resolveGucPlan, gucOp } from "./prismaRls.js";

const globalForPrisma = globalThis as unknown as {
  basePrisma: PrismaClient | undefined;
};

// Raw, un-extended client. Used by seeds/scripts and by the extension internals.
export const basePrisma =
  globalForPrisma.basePrisma ??
  new PrismaClient({
    log: process.env.NODE_ENV === "development" ? ["query", "error", "warn"] : ["error"],
  });

if (process.env.NODE_ENV !== "production") globalForPrisma.basePrisma = basePrisma;

// RLS-extended client — what every service/route imports as `prisma`.
// Each model op runs in a 2-statement transaction so the GUC + query share one
// connection (correct under a transaction-mode pooler). The GUC op uses
// basePrisma (un-extended) so it does not re-enter the extension (no recursion).
export const prisma = basePrisma.$extends({
  query: {
    $allModels: {
      async $allOperations({ args, query }) {
        const plan = resolveGucPlan(getTenantContext());
        const [, result] = await basePrisma.$transaction([gucOp(basePrisma, plan), query(args)]);
        return result;
      },
    },
  },
});

export type ExtendedPrisma = typeof prisma;
```

`basePrisma.$transaction([opA, opB])` runs both ops sequentially in one transaction on one connection and returns `[resultA, resultB]`; `query(args)` returns a `PrismaPromise` compatible with the array form — Prisma's documented RLS pattern. Every existing `import { prisma } from "../lib/prisma.js"` now gets the RLS-aware client with zero call-site edits, and `basePrisma` is available for seeds/scripts.

Create `api/prisma/rls/pilot.sql`:

```sql
-- RLS pilot: school_courses + student_course_plans (direct schoolId column).
-- GUCs: app.current_school_id (uuid as text), app.bypass_rls ('on' bypasses).
-- Idempotent: safe to re-run (drops policy before recreating).

ALTER TABLE "school_courses" ENABLE ROW LEVEL SECURITY;
ALTER TABLE "school_courses" FORCE ROW LEVEL SECURITY;
DROP POLICY IF EXISTS tenant_isolation ON "school_courses";
CREATE POLICY tenant_isolation ON "school_courses"
  USING (
    "schoolId" = current_setting('app.current_school_id', true)::uuid
    OR current_setting('app.bypass_rls', true) = 'on'
  )
  WITH CHECK (
    "schoolId" = current_setting('app.current_school_id', true)::uuid
    OR current_setting('app.bypass_rls', true) = 'on'
  );

ALTER TABLE "student_course_plans" ENABLE ROW LEVEL SECURITY;
ALTER TABLE "student_course_plans" FORCE ROW LEVEL SECURITY;
DROP POLICY IF EXISTS tenant_isolation ON "student_course_plans";
CREATE POLICY tenant_isolation ON "student_course_plans"
  USING (
    "schoolId" = current_setting('app.current_school_id', true)::uuid
    OR current_setting('app.bypass_rls', true) = 'on'
  )
  WITH CHECK (
    "schoolId" = current_setting('app.current_school_id', true)::uuid
    OR current_setting('app.bypass_rls', true) = 'on'
  );
```
